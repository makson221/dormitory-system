# Автоматизована система студентського гуртожитку

Курсовий проєкт: C#, .NET 8, Windows Forms, SQLite (ADO.NET, пакет `Microsoft.Data.Sqlite`).

## Запуск

1. Відкрийте `DormitorySystem.sln` у Visual Studio 2022 (потрібне навантаження «Розробка класичних застосунків .NET»).
2. Натисніть **F5**. Під час першої збірки NuGet автоматично завантажить пакет `Microsoft.Data.Sqlite`.
3. Під час першого запуску поруч із `.exe` створюється файл бази `dormitory.db` з демонстраційними даними
   (кімнати на 3 поверхах, 20 студентів, поселення з 1 вересня, платежі; є кілька боржників).
   Щоб почати з «чистої» бази — видаліть `dormitory.db`, і її буде створено заново.

| Логін | Пароль | Роль |
|---|---|---|
| `admin` | `admin123` | Адміністратор — повний доступ, керування користувачами, видалення записів |
| `komendant` | `komendant1` | Комендант — студенти, поселення, оплата, звіти |

## Можливості

- **Авторизація і ролі**: паролі зберігаються як хеш PBKDF2-SHA256 із сіллю; блокування облікових записів;
  обмеження на 5 спроб входу; зміна власного пароля; вихід з облікового запису.
- **Студенти**: додавання, редагування, видалення (лише адміністратор, якщо немає пов'язаних записів),
  перевірка обов'язкових полів, телефону, e-mail, унікальності студентського квитка; пільга на оплату (%);
  стовпець заборгованості; фільтр «проживають / не проживають».
- **Кімнати**: номер, поверх, кількість місць, тип (чоловіча / жіноча / будь-яка), ціна; зайнято/вільно;
  список мешканців вибраної кімнати; фільтр «лише з вільними місцями».
- **Поселення**: поселення, виселення, переселення, архів. Бізнес-правила: студент може мати лише одне
  активне поселення; немає поселення понад місткість; стать студента має відповідати типу кімнати;
  перевірка дат; попередження про борг під час виселення. Операції виконуються в транзакціях.
- **Оплата**: внесення платежів (сума підставляється автоматично), журнал за період, підсумок, сторно (адміністратор).
  Нарахування: кожен розпочатий місяць проживання × ціна кімнати × (100 − пільга)%.
- **Пошук** на кожній вкладці — за будь-яким полем, кілька слів одночасно.
- **Звіти**: заселеність кімнат, список мешканців, боржники, статистика за факультетами,
  надходження оплат по місяцях, рух мешканців за період.
- **Експорт** будь-якої таблиці у CSV (відкривається в Excel) або HTML (для друку).

## Структура проєкту

```
DormitorySystem/
├─ Program.cs                  точка входу: БД → вхід → головне вікно
├─ Models/Models.cs            класи предметної області (User, Room, Student, Accommodation, Payment, …)
├─ Data/
│  ├─ Db.cs                    доступ до SQLite: підключення, команди, транзакції, завантаження в DataTable
│  ├─ Schema.cs                DDL — структура таблиць, обмеження, індекси
│  ├─ SeedData.cs              початкові користувачі та демо-дані
│  └─ Repositories.cs          репозиторії: користувачі, кімнати, студенти, поселення, платежі
├─ Services/
│  ├─ Security.cs              хешування паролів, сеанс, автентифікація
│  ├─ AccommodationService.cs  поселення / виселення / переселення (бізнес-правила)
│  ├─ BillingService.cs        нарахування та заборгованість
│  └─ ReportService.cs         формування звітів
├─ UI/Ui.cs                    стиль таблиць, повідомлення, пошук, експорт, базова форма-діалог
├─ Forms/                      вікна: вхід, головне, діалоги редагування
└─ Pages/                      вкладки головного вікна (UserControl)
```

Інтерфейс створюється програмним кодом (без файлів `.Designer.cs`), тому файли форм відкриваються
у Visual Studio як звичайний код.

## База даних

| Таблиця | Призначення | Основні поля |
|---|---|---|
| `Users` | користувачі системи | Login (унікальний), PasswordHash, Salt, FullName, Role, IsActive |
| `Rooms` | кімнати | Number (унікальний), Floor, Capacity, Gender, PricePerMonth, Notes |
| `Students` | студенти | ПІБ, BirthDate, Gender, Faculty, Course, GroupName, StudentTicket (унікальний), Phone, Email, BenefitPercent |
| `Accommodations` | поселення (історія) | StudentId → Students, RoomId → Rooms, CheckInDate, CheckOutDate, ContractNumber |
| `Payments` | платежі | StudentId → Students, Amount, PaymentDate, Period, ReceiptNumber, UserId → Users |

Зв'язки: `Students 1—N Accommodations N—1 Rooms`, `Students 1—N Payments`, `Users 1—N Payments`.
Частковий унікальний індекс `UX_Accommodations_ActiveStudent` гарантує одне активне поселення на студента.
